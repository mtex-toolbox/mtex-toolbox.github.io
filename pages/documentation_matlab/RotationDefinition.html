A rotation is built from whichever description is at hand - three Euler angles, an axis and an angle, a matrix, a pair of directions - and MTEX converts. Whatever the input, the result is a <rotation.rotation.html rotation>, a list of rotations stored internally as quaternions.

Euler Angles

The most common description of a rotation is as three consecutive rotations about fixed axes - first about the z axis, then about the x axis, then about z again. The three angles are the Euler angles.

Three angles alone do not define a rotation. Which axes they turn about, and in which order, is a convention, and several are in use. Sorted by popularity in the texture analysis community they are

  • Bunge (phi1,Phi,phi2) - ZXZ
  • Matthies (alpha,beta,gamma) - ZYZ
  • Roe (Psi,Theta,Phi)
  • Kocks (Psi,Theta,phi)
  • Canova (omega,Theta,phi)

MTEX uses the Bunge convention by default.

{% highlight matlab %} rot = rotation.byEuler(30*degree,50*degree,10*degree) {% endhighlight %} {% highlight plaintext %} rot = rotation Bunge Euler angles in degree phi1 Phi phi2 30 50 10 {% endhighlight %}

Angles are radians throughout MTEX, which is why each of them is written as a multiple of degree. The first and the third angle are interchanged with respect to the usual notation, for the reason given in MTEX vs. Bunge Convention.

A different convention is named as an additional argument. The following rotation is a different one, although the three numbers are the same.

{% highlight matlab %} rot = rotation.byEuler(30*degree,50*degree,10*degree,'Roe') {% endhighlight %} {% highlight plaintext %} rot = rotation Bunge Euler angles in degree phi1 Phi phi2 120 50 280 {% endhighlight %}

What convention the angles are displayed in is a separate question, set by setMTEXpref and stored permanently in mtex_settings.m. The same rotation reads

{% highlight matlab %} setMTEXpref('EulerAngleConvention','Roe') rot {% endhighlight %} {% highlight plaintext %} rot = rotation Roe Euler angles in degree Psi Theta Phi 30 50 10 {% endhighlight %} {% highlight matlab %} setMTEXpref('EulerAngleConvention','Bunge') rot {% endhighlight %} {% highlight plaintext %} rot = rotation Bunge Euler angles in degree phi1 Phi phi2 120 50 280 {% endhighlight %}

Same rotation, different numbers. When Euler angles are quoted without their convention, they are ambiguous - this is the single most common source of orientations that are wrong by a fixed transformation.

Axis and Angle

Every rotation turns the sphere about one axis, so an axis and an angle describe it completely.

{% highlight matlab %} rot = rotation.byAxisAngle(vector3d.X,30*degree) {% endhighlight %} {% highlight plaintext %} rot = rotation Bunge Euler angles in degree phi1 Phi phi2 0 30 0 {% endhighlight %}

Both are read back off any rotation, however it was defined.

{% highlight matlab %} rot.axis {% endhighlight %} {% highlight plaintext %} ans = vector3d (y↓→x) x y z 1 0 0 {% endhighlight %} {% highlight matlab %} rot.angle ./ degree {% endhighlight %} {% highlight plaintext %} ans = 30.0000 {% endhighlight %}

Drawn, that is all a rotation is: an axis, and everything else swung about it. The blue arrow is the axis, the grey arrow a direction before the rotation and the red arrow the same direction afterwards.

{% highlight matlab %} v = normalize(vector3d(0.2,0.3,1)); arrow3d(1.5*rot.axis,'faceColor','blue') hold on arrow3d(1.2*v,'faceColor',[.45 .45 .45]) arrow3d(1.2*(rot*v),'faceColor','red') hold off axis off {% endhighlight %}

Rodrigues Frank Vector

The Rodrigues Frank vector packs axis and angle into a single vector: the rotational axis, scaled by \(\tan \omega/2\).

{% highlight matlab %} R = rot.Rodrigues {% endhighlight %} {% highlight plaintext %} R = vector3d (y↓→x) x y z 0.268 0 0 {% endhighlight %}

The angle is recovered from its length,

{% highlight matlab %} 2 * atan(norm(R)) ./ degree {% endhighlight %} {% highlight plaintext %} ans = 30.0000 {% endhighlight %}

and the rotation from the vector.

{% highlight matlab %} rotation.byRodrigues(R) {% endhighlight %} {% highlight plaintext %} ans = rotation Bunge Euler angles in degree phi1 Phi phi2 0 30 0 {% endhighlight %}

Rotation Matrix

A rotation is equally a \(3 \times 3\) matrix.

{% highlight matlab %} M = rot.matrix {% endhighlight %} {% highlight plaintext %} M = 1.0000 0 0 0 0.8660 -0.5000 0 0.5000 0.8660 {% endhighlight %}

Its columns are where the specimen axes X, Y and Z end up after the rotation. Rotating X gives the first column of M back.

{% highlight matlab %} rot * vector3d.X {% endhighlight %} {% highlight plaintext %} ans = vector3d (y↓→x) x y z 1 0 0 {% endhighlight %}

Conversely a matrix defines a rotation.

{% highlight matlab %} rot = rotation.byMatrix(M) {% endhighlight %} {% highlight plaintext %} rot = rotation Bunge Euler angles in degree phi1 Phi phi2 0 30 0 {% endhighlight %}

Defined by What it Does

Often the rotation is not known in any parametrisation, only by what it has to achieve. Given two non-collinear pairs of directions there is exactly one rotation taking u1 to v1 and u2 to v2.

{% highlight matlab %} u1 = vector3d.X; v1 = vector3d.Y; u2 = vector3d.Z; v2 = vector3d.Z; rot = rotation.map(u1,v1,u2,v2) {% endhighlight %} {% highlight plaintext %} rot = rotation Bunge Euler angles in degree phi1 Phi phi2 90 0 0 {% endhighlight %}

This asks the impossible unless the angle between u1 and u2 equals the angle between v1 and v2, and MTEX raises an error if it does not. Given only one pair, the rotation with the smallest angle taking the first direction to the second is returned.

{% highlight matlab %} rot = rotation.map(vector3d.Z,vector3d.Y) {% endhighlight %} {% highlight plaintext %} rot = rotation Bunge Euler angles in degree phi1 Phi phi2 180 90 180 {% endhighlight %}

With more directions than a rotation can satisfy exactly - measurements, say - rotation.fit returns the rotation for which rot * left is closest to right.

{% highlight matlab %} % five random directions left = vector3d.rand(5); % rotate them and perturb them a little right = rot * left + 0.1 * vector3d.rand(1,5); rotation.fit(left,right) {% endhighlight %} {% highlight plaintext %} ans = rotation Bunge Euler angles in degree phi1 Phi phi2 182.717 92.0857 177.089 {% endhighlight %}

The recovered rotation is the one used above, up to the perturbation.

Random Rotations

rotation.rand draws rotations uniformly, which is the quickest way to try something out on data that has no structure.

{% highlight matlab %} rot = rotation.rand(100); length(rot) {% endhighlight %} {% highlight plaintext %} ans = 100 {% endhighlight %}

Rotations following a given distribution rather than a uniform one are the subject of Random Sampling.

Quaternions

Finally a rotation is defined by the four quaternion coordinates it is stored in.

{% highlight matlab %} q = quaternion(1,0,0,0) rot = rotation(q) {% endhighlight %} {% highlight plaintext %} q = quaternion a b c d 1 0 0 0 rot = rotation Bunge Euler angles in degree phi1 Phi phi2 0 0 0 {% endhighlight %}

This one is the identity, the rotation by an angle of zero, which is also written rotation.id.
