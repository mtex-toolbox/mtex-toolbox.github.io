--- title: "Symmetrically Equivalent Orientations" sidebar: documentation_sidebar permalink: OrientationSymmetry.html folder: documentation toc: false --- Symmetrically Equivalent Orientations edit page

An orientation never stands alone. Every symmetry operation of the crystal produces a rotation that maps the crystal frame onto the specimen frame just as well, and no measurement can tell them apart. The same is true for symmetry of the specimen. An orientation is therefore a whole class of rotations, and MTEX works with the class rather than with the representative that happened to be written down.

{% highlight matlab %} plottingConvention.default('y↑→x'); % hexagonal crystal symmetry, 6 rotations about the c axis cs = crystalSymmetry('6') {% endhighlight %} {% highlight plaintext %} cs = crystalSymmetry (⊙c→a) symmetry : 6 elements : 6 a, b, c : 1, 1, 1 reference frame: X||a*, Y||b, Z||c {% endhighlight %} {% highlight matlab %} % specimen symmetry with a twofold axis along z ss = specimenSymmetry('112') {% endhighlight %} {% highlight plaintext %} ss = monoclinic specimenSymmetry (y↑→x) {% endhighlight %} {% highlight matlab %} % a random orientation ori = orientation.rand(cs,ss) {% endhighlight %} {% highlight plaintext %} ori = orientation (6 → y↑→x (112)) Bunge Euler angles in degree phi1 Phi phi2 156.958 161.468 197.878 {% endhighlight %}

Which Side Acts

An orientation takes crystal coordinates to specimen coordinates, so crystal symmetry acts on its input, from the right, and specimen symmetry on its output, from the left. The six crystal operations give

{% highlight matlab %} % symmetrically equivalent orientations with respect to crystal symmetry ori * cs {% endhighlight %} {% highlight plaintext %} ans = orientation (6 → y↑→x (112)) size: 1 × 6 Bunge Euler angles in degree phi1 Phi phi2 156.958 161.468 197.878 156.958 161.468 257.878 156.958 161.468 317.878 156.958 161.468 17.8785 156.958 161.468 77.8785 156.958 161.468 137.878 {% endhighlight %}

Only the third Euler angle \(\varphi_2\) changes, in steps of \(60^\circ\), because \(\varphi_2\) is the rotation applied first, i.e. the one acting in crystal coordinates - which is exactly where the crystal symmetry sits.

Specimen symmetry produces the other kind of equivalence.

{% highlight matlab %} % symmetrically equivalent orientations with respect to specimen symmetry ss * ori {% endhighlight %} {% highlight plaintext %} ans = orientation (6 → y↑→x (112)) size: 2 × 1 Bunge Euler angles in degree phi1 Phi phi2 156.958 161.468 197.878 336.958 161.468 197.878 {% endhighlight %}

Now \(\varphi_1\) moves instead, the angle applied last. Both together give the full class, \(2 \times 6 = 12\) orientations.

{% highlight matlab %} ss * ori * cs {% endhighlight %} {% highlight plaintext %} ans = orientation (6 → y↑→x (112)) size: 2 × 6 Bunge Euler angles in degree phi1 Phi phi2 156.958 161.468 197.878 336.958 161.468 197.878 156.958 161.468 257.878 336.958 161.468 257.878 156.958 161.468 317.878 336.958 161.468 317.878 156.958 161.468 17.8785 336.958 161.468 17.8785 156.958 161.468 77.8785 336.958 161.468 77.8785 156.958 161.468 137.878 336.958 161.468 137.878 {% endhighlight %}

symmetrise is the shortcut for that product.

{% highlight matlab %} length(symmetrise(ori)) {% endhighlight %} {% highlight plaintext %} ans = 12 {% endhighlight %}

What This Looks Like in a Pole Figure

One orientation and one crystal direction give not one pole but a whole set of them.

{% highlight matlab %} h = Miller(1,0,0,cs); plotPDF(ori,h,'MarkerSize',10,'figSize','small') {% endhighlight %}
{% include inline_image.html file="OrientationSymmetry_01.png" %}

The dots are distinct specimen directions, but each comes from a member of the same crystallographically equivalent direction family. Which member a calculation produces depends on the representative used for the orientation, so symmetry-aware comparisons take the full family into account.

Coincidences

For orientations that sit on a symmetry axis, several of the equivalent rotations coincide. The identity orientation is the extreme case: its class has 12 members but only 6 distinct ones, which the option 'unique' removes.

{% highlight matlab %} length(symmetrise(orientation.id(cs,ss),'unique')) {% endhighlight %} {% highlight plaintext %} ans = 6 {% endhighlight %}

Symmetry in Every Computation

Because the class is what matters, the angle between two orientations is the smallest angle over all equivalent pairs. Comparing a random orientation with each of the symmetric equivalents of the Goss orientation gives one and the same number.

{% highlight matlab %} ori = orientation.rand(cs); angle(ori,symmetrise(orientation.goss(cs))) ./ degree {% endhighlight %} {% highlight plaintext %} ans = 138.9364 138.9364 138.9364 138.9364 138.9364 138.9364 {% endhighlight %}

Switching symmetry off shows what those rotations really are: six different angles, of which the number above is the smallest.

{% highlight matlab %} angle(ori,symmetrise(orientation.goss(cs)),'noSymmetry') ./ degree {% endhighlight %} {% highlight plaintext %} ans = 160.6304 179.0557 158.9692 144.1395 138.9364 145.1306 {% endhighlight %}

The 'noSymmetry' flag is available wherever the distinction matters, among others for dot, unique and calcCluster. Reach for it when a number comes out smaller than expected - and leave it alone otherwise, since the symmetry-aware answer is the physically meaningful one.
