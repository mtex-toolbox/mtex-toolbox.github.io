A direction in the specimen is a variable of type <vector3d.vector3d.html vector3d>. It is stored as the three Cartesian coordinates \(x\), \(y\), \(z\) of a point, and everything that follows - angles, rotations, pole figures - is computed from those three numbers.

{% highlight matlab %} plottingConvention.default('y↑→x'); {% endhighlight %}

Cartesian Coordinates

The direct way to define a direction is by its coordinates with respect to the specimen axes X, Y and Z.

{% highlight matlab %} v = vector3d(1,2,3) {% endhighlight %} {% highlight plaintext %} v = vector3d (y↑→x) x y z 1 2 3 {% endhighlight %}

The output is a table with one row per vector, here a single one. Drawing it puts a point on the sphere, seen from above.

{% highlight matlab %} plot(v,'grid','upper') {% endhighlight %}
{% include inline_image.html file="VectorDefinition_01.png" %}

The point sits in the upper right quadrant, because \(x\) and \(y\) are both positive, and away from the rim, because \(z\) is positive as well. Where it lands does not depend on how long the vector is - only on which way it points. The length is available as the norm,

{% highlight matlab %} norm(v) {% endhighlight %} {% highlight plaintext %} ans = 3.7417 {% endhighlight %}

and normalize scales it to one without moving the point.

{% highlight matlab %} norm(normalize(v)) {% endhighlight %} {% highlight plaintext %} ans = 1 {% endhighlight %}

Single coordinates are read and written as properties.

{% highlight matlab %} v.x {% endhighlight %} {% highlight plaintext %} ans = 1 {% endhighlight %} {% highlight matlab %} v.x = 0 {% endhighlight %} {% highlight plaintext %} v = vector3d (y↑→x) x y z 0 2 3 {% endhighlight %}

Polar Coordinates

A direction is equally well described by two angles: the polar angle \(\theta\), measured away from the Z axis, and the azimuth angle \(\rho\), measured in the XY plane away from the X axis. This is what vector3d.byPolar takes.

{% highlight matlab %} v = vector3d.byPolar(60*degree,45*degree) {% endhighlight %} {% highlight plaintext %} v = vector3d (y↑→x) x y z 0.612 0.612 0.5 {% endhighlight %}

Angles are radians throughout MTEX, so an angle in degree is written as a multiple of degree. Both angles are also properties, and they read back in radians.

{% highlight matlab %} plot(v,'grid','upper') {% endhighlight %}
{% include inline_image.html file="VectorDefinition_02.png" %}
{% highlight matlab %} v.rho ./ degree % the azimuth angle in degree {% endhighlight %} {% highlight plaintext %} ans = 45.0000 {% endhighlight %} {% highlight matlab %} v.theta ./ degree % the polar angle in degree {% endhighlight %} {% highlight plaintext %} ans = 60.0000 {% endhighlight %}

The Specimen Axes

The three specimen axes themselves are vector3d.X, vector3d.Y and vector3d.Z. They are the readable way to write down a direction that is tied to the specimen rather than to a measurement.

{% highlight matlab %} v = vector3d.X + 2 * vector3d.Y {% endhighlight %} {% highlight plaintext %} v = vector3d (y↑→x) x y z 1 2 0 {% endhighlight %}

Their names are a convention of the experiment: for rolled material X is usually the rolling direction, Y the transverse direction and Z the normal direction of the sheet.

Many Directions at Once

One vector3d variable holds an entire list of directions, and this is how directional data is handled in MTEX - not as a loop over single vectors. Passing arrays of coordinates gives one vector per entry.

{% highlight matlab %} v = vector3d((1:5),0,1) {% endhighlight %} {% highlight plaintext %} v = vector3d (y↑→x) size: 1 × 5 x y z 1 0 1 2 0 1 3 0 1 4 0 1 5 0 1 {% endhighlight %}

The list has a shape, just as a numeric array does, and it is indexed the same way.

{% highlight matlab %} size(v) {% endhighlight %} {% highlight plaintext %} ans = 1 5 {% endhighlight %} {% highlight matlab %} v(2) {% endhighlight %} {% highlight plaintext %} ans = vector3d (y↑→x) x y z 2 0 1 {% endhighlight %}

Coordinates that already sit in a matrix are read row by row by vector3d.byXYZ, one vector per row.

{% highlight matlab %} xyz = [1 0 0; 0 1 0; 1 1 1]; v = vector3d.byXYZ(xyz) {% endhighlight %} {% highlight plaintext %} v = vector3d (y↑→x) size: 3 × 1 x y z 1 0 0 0 1 0 1 1 1 {% endhighlight %}

Prefer byXYZ over passing the matrix to the constructor. The constructor accepts both readings - a \(3 \times N\) matrix by columns and an \(N \times 3\) matrix by rows - so for a \(3 \times 3\) matrix it has to guess, and it warns and reads by columns. byXYZ never guesses.

Random directions are useful to try something out, and come from vector3d.rand.

{% highlight matlab %} v = vector3d.rand(100); plot(v,'upper','grid','MarkerSize',4) {% endhighlight %}

Plotting Conventions

Which way X points on the page is a property of the drawing, not of the data. Passing a different plottingConvention redraws the same vector seen from somewhere else.

{% highlight matlab %} v = vector3d(1,2,3); plot(v,'how2plot',plottingConvention('z←↑y'),'grid') {% endhighlight %}
{% include inline_image.html file="VectorDefinition_04.png" %}

Nothing about v changed - only the camera did. To align every plot of a session the same way, set plottingConvention.default, as the first line of this page does. The alignment of the axes is treated in Axes Alignment.
