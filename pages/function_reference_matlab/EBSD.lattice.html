--- title: "EBSD.lattice" sidebar: function_reference_sidebar permalink: EBSD.lattice.html folder: function_reference toc: false --- EBSD.lattice edit page

the virtual lattice this EBSD's measurements sit on

Computed on every access (like ebsd.orientations) rather than cached on the object - simplest to keep correct since pos/unitCell can change underneath it, at the cost of recomputing latticeBasis + the per-pixel index on each call. A caching option could be added later if this ever shows up as a bottleneck.

This is the single canonical place that turns ebsd.unitCell + ebsd.pos into a lattice basis and a per-pixel integer index - previously reimplemented independently (and not always robustly) in gridIndex, gridComponents, spatialDecompositionGrid, generateUnitCells and calcMesh.

Syntax

{% highlight matlab %} g = ebsd.lattice {% endhighlight %}

Output

g struct with fields
A 2 × 2 lattice basis, columns are the grid step vectors
stencil k × 2 integer neighbour offsets (k = 4 square, 6 hex)
dxy representative spacing = mean column norm of A
origin 1 × 2 physical position corresponding to ij = [0 0]
ij nEbsd × 2 integer lattice index of every pixel, robust to smooth (e.g. trapezoidal) grid distortion
Note: ij is RELATIVE to this data's own extent. A phase subset therefore gets its own origin; do not compare indices across different subsets expecting a common frame.
