# MTEX website

The source of <https://mtex-toolbox.github.io>, a Jekyll site built on the
[Documentation Theme for Jekyll](https://idratherbewriting.com/documentation-theme-jekyll/index.html).
GitHub Pages serves the `master` branch of
`mtex-toolbox/mtex-toolbox.github.io` and builds it on every push.

Most pages are generated by MATLAB from the MTEX sources (see
[Rebuilding the documentation](#rebuilding-the-documentation)). `CLAUDE.md`
has the detailed notes on the build.

## Two sites

| | Live site | Preview |
|---|---|---|
| Address | <https://mtex-toolbox.github.io> | <https://mtex-playground.github.io> |
| Site checkout | `web/`, branch `master` | `web-next/`, branch `redesign` |
| MTEX checkout | `master/` | `mtex-next/`, branch `docs-next` |
| Pages repository | `mtex-toolbox/mtex-toolbox.github.io` | `mtex-playground/mtex-playground.github.io` |
| Figures repository | `mtex-toolbox/figures` | `mtex-playground/figures` |
| Deploy | `./update.sh` | `tools/deploy-next.sh` |

The preview is where the redesign and the new documentation structure are
built before they replace the live site. Search engines are kept away from it:
it is built with `_config_next.yml`, which marks every page `noindex` and makes
`robots.txt` block all crawlers.

The directories are siblings in one working folder, next to the `makeDoc/`
toolbox:

```
mtex/
├── master/       MTEX, the branch the live documentation follows
├── mtex-next/    MTEX worktree, branch docs-next (from develop)
├── makeDoc/      the DocHelp publishing toolbox, shared by both
├── web/          this repository, master
│   └── figures/  clone of mtex-toolbox/figures
└── web-next/     worktree of this repository, branch redesign
    └── figures/  clone pushing to mtex-playground/figures
```

## Setting up

From the working folder that holds the MTEX checkout `master/`:

```bash
git clone git@github.com:mtex-toolbox/mtex-toolbox.github.io.git web
git clone git@github.com:mtex-toolbox/figures.git web/figures
cd web
bundle config set --local path ~/.local/share/gem/bundle   # if the system gem directory is not writable
bundle install
```

For the preview, add the two worktrees and a figures clone that pushes to the
preview organisation. Run this from the working folder that holds `master/` and
`web/`:

```bash
git -C master fetch origin develop
git -C master worktree add -b docs-next ../mtex-next origin/develop
git -C web worktree add -b redesign ../web-next master
git clone web/figures web-next/figures
git -C web-next/figures remote set-url origin git@github.com:mtex-playground/figures.git
(cd web-next && bundle config set --local path ~/.local/share/gem/bundle && bundle install)
```

## Looking at a site locally

```bash
bundle exec jekyll serve                                        # live configuration
bundle exec jekyll serve --config _config.yml,_config_next.yml  # preview configuration
```

Both serve at <http://127.0.0.1:4000>. The preview configuration excludes
`figures/` from the build, so figures do not show locally with it; use the
first command to check pages with their figures.

## Rebuilding the documentation

Inside MATLAB, from the `matlab/` folder of the site checkout. Start MATLAB in
the MTEX checkout that belongs to it (`master/` for the live site, `mtex-next/`
for the preview), so that `startup_mtex` puts the right sources on the path.

```matlab
makeDoc                          % everything: function reference, documentation, examples
makeDoc('doc')                   % only the documentation pages
makeDoc('file','EBSDTutorial')   % one page
makeDoc('checkLinks')            % dead-link scan
```

The figures go to `../figures`, the figures clone of that site checkout.
`CLAUDE.md` lists all options and explains the image diff and the revert pass.

## Deploying the live site

From `web/`, on `master`:

```bash
./update.sh --dry-run   # show what would be committed
./update.sh             # publish figures, then commit and push the pages
./update.sh --all       # take every change, not only what a build writes
```

`update.sh` first publishes changed figures through `tools/deploy-figures.sh`,
then stages only what a build writes (`pages`, `images`, `_data/sidebars`,
`search.json`), shows it, asks, commits and pushes `master`. GitHub Pages
rebuilds the site within a few minutes. The script refuses to run on any
branch other than `master`.

To publish figures alone:

```bash
tools/deploy-figures.sh --dry-run
tools/deploy-figures.sh
```

The figures repository keeps a single commit: every deploy replaces it and
force-pushes.

## Deploying the preview

From `web-next/`:

```bash
tools/deploy-next.sh --dry-run   # build into ../web-next-site, publish nothing
tools/deploy-next.sh             # build, publish figures, push the pages
```

The script builds the site locally with `_config.yml` and `_config_next.yml`,
publishes changed figures to `mtex-playground/figures`, and force-pushes the
built pages as one commit to `mtex-playground/mtex-playground.github.io`. A run
takes about a minute and a half, and GitHub needs another minute or two before
the new version is served. It refuses to run if `figures/` does not push to
`mtex-playground`.

The preview is built locally rather than by GitHub Pages because Pages reads
only `_config.yml`.

## Keeping the preview up to date

Changes to the live site and the MTEX sources carry on as usual. Merge them
into the preview branches from time to time:

```bash
git -C web-next merge master          # site: news, workshop pages, fixes
git -C mtex-next fetch origin
git -C mtex-next merge origin/develop # MTEX sources and documentation
```

## Replacing the live site with the preview

1. Merge `redesign` into `master` in `web/`, and `docs-next` into `develop`
   in the MTEX repository.
2. Rebuild the documentation in `web/` with `makeDoc('force')`.
3. Deploy with `./update.sh`.

Page URLs are the source file names, so no link changes and no redirects are
needed. `_config_next.yml` and `tools/deploy-next.sh` can stay: the live build
ignores them.
